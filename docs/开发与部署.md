# 开发与部署

[返回项目介绍](../README.md) · [使用指南](使用指南.md)

## 运行架构

开发时，Vite 在 `5178` 端口提供 React 前端，将 `/api` 请求代理到 `3001` 的 Express。生产构建后，Express 同时提供 `dist/` 静态文件和 API，因此可以使用同一个域名。

数据库由 sql.js 在单个 Node.js 进程中处理事务，再写入 SQLite 文件。前端不直接访问数据库，标准接口不返回服务端判题答案。

## 本地开发

环境：Node.js 20.18+，建议 Node.js 24，使用仓库锁定的 npm 依赖。

```bash
npm ci
npm run dev
```

- 前端：`http://localhost:5178`。
- API：`http://localhost:3001/api/health`。
- 首次运行自动创建 `.runtime/wordland.sqlite`。
- 默认开发监听 `0.0.0.0`，仅在本机或可信局域网使用；不同主机或端口作为访问来源时，需同步配置 `APP_ORIGINS`。

如果系统文件监听数量受限，可以分两个终端启动，避免后端 watch：

```bash
node server/index.js
```

```bash
npx vite --host 0.0.0.0
```

Vite 仍出现监听限制时，可在其终端设置 `CHOKIDAR_USEPOLLING=true` 后启动。

## 环境变量

`.env.example` 只包含示例值。本地服务不会自动读取 `.env`，需要在终端、进程管理器或托管平台设置，或用支持该参数的 Node.js 显式加载。

| 变量 | 默认值 / 用途 |
| --- | --- |
| `PORT` | `3001`，API / 生产服务监听端口 |
| `DATABASE_PATH` | 默认项目目录下的 `.runtime/wordland.sqlite`；可设置为持久卷中的绝对路径 |
| `APP_ORIGINS` | 默认允许 `http://localhost:5178,http://127.0.0.1:5178`；多个来源用英文逗号分隔 |
| `SECURE_COOKIES` | 默认 `false`；通过 HTTPS 对外提供服务时设为 `true` |
| `NODE_ENV` | 设为 `production` 后，Express 同时提供 `dist/` 中的前端构建 |

例如复制示例配置并补充生产配置后，显式加载：

```bash
node --env-file=.env server/index.js
```

此命令是否提供构建页面取决于 `.env` 中的 `NODE_ENV`。不要将 `.env`、SQLite 数据库或实际部署凭据提交到 Git。

## 构建和生产运行

```bash
npm run build
npm start
```

`npm start` 使用 macOS / Linux 的环境变量语法。Windows PowerShell：

```powershell
$env:NODE_ENV = "production"
node server/index.js
```

构建后访问 `http://localhost:3001`。生产启动必须与项目根目录、`server/`、`data/`、`public/`、`dist/` 及安装的运行依赖配套，不能仅复制前端构建后期待账号接口工作。

### 公网自部署

1. 在支持长期运行 Node.js 的服务器或平台部署源码并执行 `npm ci`、`npm run build`。
2. 配置 `NODE_ENV=production`、持久化的 `DATABASE_PATH` 和自己的 `APP_ORIGINS`。
3. 通过平台或反向代理配置自己的域名与 HTTPS，设置 `SECURE_COOKIES=true`。
4. 运行单个应用进程，确保数据库目录可写，保持数据在进程或容器重启后仍然存在。
5. 由部署方完善备份、恢复、监控和账号管理，再按实际使用规模评估数据库方案。

不要把示例演示域名直接当作自己的 `APP_ORIGINS`。仅部署到 GitHub Pages 不能提供 Express API、登录和服务端历史记录。

本仓库开放的是可独立运行的 Node.js / SQLite 版本。现有在线演示的托管平台专用源码目录、站点绑定和实际数据库未纳入仓库；在线记录也不包含在源码中。

## 备份与恢复

本地默认数据库为 `.runtime/wordland.sqlite`。它保存账号哈希、会话与学习记录，应作为私有数据管理。

- 使用单进程服务；备份前停止应用，再复制完整数据库文件到私有位置。
- 恢复时先停止应用，用备份替换所配置的数据库文件，再启动服务。
- 不要在运行中删除数据库，也不要把数据库上传到 Issue 或公开仓库。
- 公开源码不会自动备份在线演示数据。

## 常用脚本

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动前端和 API 开发服务 |
| `npm run build` | TypeScript 检查与前端生产构建 |
| `npm start` | macOS / Linux 启动生产服务 |
| `npm test` | 在需要验证改动时运行已有 API 测试 |
| `npm run curriculum:export` | 导出课程清单 |
| `npm run import:primary -- --source /path/to/语文.json` | 从上游源文件重新导入小学知识点 |
| `npm run import:grade1 -- --source /path/to/语文.json` | 重新导入一年级知识点 |

普通运行不需要重新导入数据。导入与生成会修改相应数据文件，操作前阅读脚本和 [数据来源说明](../data/ATTRIBUTION.md)。

## 扩充课程

- 课程定义主要位于 `server/lessons.js`、`server/upper-lessons.js`、`server/term-expansion.js` 和 `server/curriculum/`。
- 题目、答案、提示、解释和知识目标在服务端定义；不要仅修改界面文字而忘记答案或来源映射。
- 内容调整涉及已有学习记录时，应考虑课程内容版本和恢复逻辑。
- 修改拼音材料时，同时核对 `practice`、听音目标、录音文件以及对应封面。
- 现代教材全文和未获授权素材不要直接复制到仓库；引用知识点保留 ID 和出处。
