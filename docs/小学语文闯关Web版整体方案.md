# 小学语文闯关 Web 版整体方案

产品暂名：**语文小侦探：文字王国历险**  
版本：V1.0 产品规划稿  
日期：2026 年 10 月 21 日  
文档状态：产品与开发范围规划，尚未进入软件实现。

## 1. 产品定位与目标

面向小学一至六年级学生，提供兼具故事探索、语文实践和持续学习记录的 Web 学习软件。使用同一网址，适配 PC、手机和平板；注册登录后，在不同设备上继续学习。

孩子在文字王国扮演小侦探，通过识字、阅读、整理线索、解释观点和创作作品推动剧情。随着年级升高，任务从听音识字逐步发展为阅读调查和综合表达。

产品需要同时实现三个目标：

1. 孩子能独立看懂任务、完成操作，并愿意探索下一段故事。
2. 每个活动对应明确的学习目标，提供有帮助的示范、提示和解释。
3. 家长能够查看实际学习历史、独立完成情况和需要复习的内容。

平台采用“全六年架构、内容分批上线”。年级、学期、教材版本和内容发布状态分别管理。尚未制作完成的内容标明“筹备中”，不能展示为完整可学课程。

## 2. 使用对象与账号关系

| 使用对象 | 主要需求 | 产品支持 |
|---|---|---|
| 一至二年级学生 | 听懂指令、认识字词、简单表达 | 语音引导、大图、大按钮、少量文字 |
| 三至四年级学生 | 自主阅读、整理信息、观察与习作 | 阅读证据选择、线索整理、片段表达 |
| 五至六年级学生 | 综合阅读、有依据地表达、修改作品 | 多材料阅读、调查笔记、作品草稿 |
| 家长 | 管理账号、了解学习过程、继续陪伴 | 注册登录、学习档案、历史记录、设置 |
| 内容维护人员 | 编写与校对关卡、发布内容 | 首发采用结构化内容文件与发布流程，后续建设管理后台 |

账号由家长或监护人管理，学习记录归属账号下的学习档案。首发提供一个学习档案，包含昵称、头像、年级和学期；数据结构预留多个学习档案，后续支持家庭中不同孩子分别学习。

学习档案不要求填写孩子真实姓名、学校或联系方式。身份账号与学习档案分开，切换年级不会清空原有历史。

## 3. 一至六年级课程与玩法

### 3.1 年级递进

| 年级 | 成长身份 | 学习重点 | 代表玩法 | 代表成果 |
|---|---|---|---|---|
| 一年级 | 文字启蒙员 | 拼音、识字、基本书写、倾听、简单句 | 听音找字、字图配对、拼音拼合 | 图文小故事、完整口头表达 |
| 二年级 | 词句探索员 | 独立识字、词语搭配、句子顺序、短文与写话 | 修复告示、整理句子、人物配对 | 连贯的几句话、简短复述 |
| 三年级 | 故事调查员 | 联系上下文、提取信息、复述、观察与习作 | 修复来信、圈选证据、观察记录 | 观察手册、具体片段 |
| 四年级 | 阅读研究员 | 概括、提问、人物理解、过程表达 | 案件时间线、人物档案、片段修改 | 有依据的解释、清楚的事件经过 |
| 五年级 | 文字策划员 | 有目的阅读、资料整合、表达方法、分步写作 | 多材料调查、新闻编辑、说明书制作 | 调查简报、修改后的习作 |
| 六年级 | 王国记录者 | 综合阅读、观点与依据、整本书交流、综合表达 | 材料比较、主题研究、毕业作品 | 有依据的看法、完整主题作品 |

拼音辅助识字、字词书写、句段理解、阅读探究、古诗文化、口语交流和写作表达持续贯穿六年。表格表示各年级侧重方向，具体顺序需结合课标和所选教材核对。

### 3.2 十二学期地图

| 年级 | 上学期地图 | 下学期地图 |
|---|---|---|
| 一年级 | 声音森林 | 汉字小镇 |
| 二年级 | 词语集市 | 故事花园 |
| 三年级 | 来信港湾 | 观察山谷 |
| 四年级 | 人物剧场 | 问题研究所 |
| 五年级 | 资料群岛 | 编辑工坊 |
| 六年级 | 观点之城 | 毕业远航 |

地图和案件是原创故事包装，不等同于教材单元。后台保留每个关卡与教材版本、册次、章节及学习目标的对应关系。

### 3.3 初步内容规模

- 6 个年级、12 个学期地图。
- 每学期初步安排 4 个剧情章节，每章 6 个主线关卡，共 24 关。
- 全六年初步规划 288 个主线关卡。
- 每关聚焦 1～2 个主要学习目标，配置 3～5 个活动；综合作品关根据任务拆成多个短步骤。
- 复习变式、课外阅读、纸笔活动与作品任务另行配置。

以上数量用于估算制作规模，不作为完整覆盖课程或掌握知识的依据。每学期发布前，单独核对学习目标覆盖表、内容质量和难度。

## 4. 学习与闯关流程

### 4.1 标准学习流程

进入地图 → 选择案件 → 了解任务 → 获得示范 → 独立尝试 → 查看解释 → 迁移运用 → 完成故事 → 保存成果。

每次进入优先显示“继续上次冒险”，同时允许选择已发布内容和复习任务。进入新年级可以从对应内容开始，不要求先通关此前所有年级。

### 4.2 一关的具体体验

示例案件：《寄错的秋日来信》。

1. 邮递员请求帮助，孩子读或听一段简短剧情。
2. 根据上下文补全信中词语，信件对应位置恢复清晰。
3. 整理句子顺序，地图出现新的线索。
4. 阅读短文，点选能说明收信人身份的依据。
5. 用学过的方法解决一个新情境，完成委托。
6. 获得故事纪念卡，查看本次学习内容和后续复习建议。

场景变化与学习动作关联。剧情文字长度、题目字量、材料数量和操作复杂度随年级调整。

### 4.3 提示、反馈与复习

- 第一次遇到新玩法提供可跳过的操作示范。
- 答错先给方向性提示，再给例子与解释，并允许重试。
- 答对后简短说明理由，阅读题尽量指向原文依据。
- 使用提示、首次答案和重试结果分别记录。
- 帮助完成当前任务后，可进入后续剧情；待巩固目标进入复习安排。
- 复习使用不同材料或题目变式，记录跨次表现。
- 学习状态使用“初次接触、能独立完成、待复习”等可解释标签；规则需在试用后校准。

一次答对、完成剧情或获得奖励，都不直接等于掌握知识。初始阶段通过不同题目的独立完成和后续复习形成学习证据。

### 4.4 活动形式与判定

| 活动形式 | 交互 | 反馈方式 |
|---|---|---|
| 听音、选字、配对 | 点击、选择、播放 | 依据校对后的答案即时反馈 |
| 排序、分类、拼合 | 点选放置或拖动 | 兼容合理答案，解释排列或分类依据 |
| 阅读找证据 | 点选句子或段落 | 反馈证据与问题的对应关系 |
| 复述与口语 | 示范、亲子交流；录音回放为后续功能 | 提供可理解的观察要点，初期不做自动口语评分 |
| 纸笔书写 | 规范示范、线下练习 | 由孩子或家长确认完成，记录为活动完成 |
| 写话、习作 | 分步输入、草稿保存、修改清单 | 提供多样示例与评价要点，首发不做单一自动作文评分 |

选择题正确率只适用于对应题型；书写、口语和作品活动分别展示完成情况、反馈及修改记录。

## 5. 趣味性设计

### 5.1 故事与角色

小书狐作为共同搭档，承担任务说明、提示和反馈。配角各有明确需求：找回信件、修复地图、整理展览、编写小报。每个剧情章节包含开端、若干任务和可见的结局。

### 5.2 奖励与成长

- **探索奖励**：完成案件后解锁地点、故事页和场景变化。
- **侦探手册**：收藏字词、诗句、阅读方法和自己的观察。
- **书屋布置**：用任务奖励兑换书架、植物、灯具等装饰。
- **案件纪念章**：按完成的具体项目获得，展示清楚的取得条件。
- **年级作品集**：保存孩子的作品与修改版本，逐年形成学习纪念册。

奖励由服务端按完成记录发放，同一奖励事件只能领取一次。重玩可以巩固学习，奖励规则单独说明。

默认使用个人成长反馈；一段任务完成后提供明确结束点和休息提示。连续学习记录采用鼓励性展示，不因中断清空已获得成果。

## 7. PC、手机、平板适配

所有终端访问同一 Web 产品，复用账号、内容与学习记录。布局依据可用宽度变化，不仅依赖设备名称；横竖屏均保持完整操作。

| 终端 | 布局与操作 | 学习体验 |
|---|---|---|
| 手机 | 单列、竖向地图、底部主要导航；触控优先 | 剧情和题目逐步展示，避免左右挤压 |
| 平板 | 适度双栏或大幅场景；触控优先 | 阅读材料与题目可并排，竖屏自动回到单列 |
| PC | 侧边导航、较宽场景、材料与任务分栏 | 支持鼠标、键盘和较长文字输入 |

初步布局范围：窄屏小于 768px，中等宽度 768～1199px，宽屏从 1200px 起。断点根据实际内容可读性调整。

共同要求：

- 内容页不出现横向溢出；长文本和较大系统字号可正常换行。
- 主要触控区域按至少 48px 设计，选项之间保留清楚间隔。
- 拖动任务提供点选放置替代方式，核心操作不依赖悬停。
- PC 支持键盘操作，触控设备不要求精确点击细小区域。
- 正文使用清晰的中文字体；学习正文以 20～24px 为初步起点，允许调整。
- 文本与背景保持足够对比度，正确或错误状态同时使用文字和图形说明。
- 浏览器缩放、软键盘弹出、屏幕旋转后，当前输入与作答状态保留。
- 图片和动画采用按需加载；音频加载失败提供重试和文字替代。
- 默认尊重减少动态效果设置；音乐、音效、朗读分别可控。

验收重点尺寸包括 360px、390px、768px、1024px、1366px 和 1440px，同时检查平板横竖屏、手机软键盘和 PC 键盘导航。

视觉采用绘本插画、纸张质感、柔和场景色与清楚的交互按钮。低年级减少装饰干扰，高年级逐步使用调查手册与资料册的视觉表达。

## 8. 注册、登录与账号基础功能

### 8.1 首发认证方案

首发采用邮箱与密码注册，包含邮箱验证、密码登录、找回密码、退出登录和会话过期处理。手机验证码、第三方登录作为后续扩展，避免首发同时依赖多种认证服务。

注册流程：填写邮箱与密码 → 验证邮箱 → 建立学习档案 → 选择年级学期 → 进入地图。邮箱投递服务属于正式上线依赖；开发环境可以使用测试收件箱，但不能将邮件未发送展示为发送成功。

登录后读取已有学习档案与进度。会话过期时保留当前未提交内容，引导重新登录，再将内容同步到原学习档案。

### 8.2 游客体验与转注册

游客可体验指定样章，浏览器本地保存体验记录，并标注“体验进度仅保存在当前浏览器”。游客暂不拥有跨设备同步能力。

注册或登录后，展示可导入的游客记录，由用户选择导入目标档案。导入按唯一记录标识去重，已有历史保留；不同档案之间不能静默混合。

### 8.3 认证与数据边界

- 密码由成熟的认证组件进行安全哈希处理，不保存明文。
- 登录会话使用安全的 HttpOnly Cookie；会话信息不作为普通业务数据存入浏览器本地存储。
- 注册、登录、验证与恢复接口具备频率限制；验证和重置链接设置有效期。
- 服务端逐次核验学习档案归属，不能仅依赖前端传来的账号或档案编号。
- 提供退出当前设备功能；密码重置后使旧会话失效。
- 账号设置提供学习数据导出与账号删除入口；删除前清楚说明影响范围。
- 云端录音、作品附件等功能增加前，单独设计授权、保存与删除规则。

## 9. 学习历史与跨设备进度

### 9.1 保存内容

| 记录 | 保存字段与用途 |
|---|---|
| 学习活动记录 | 档案、年级学期、关卡、内容版本、开始与结束时间、有效学习时长、完成状态 |
| 作答记录 | 题目标识、题目版本、提交内容、首次与重试结果、提示使用、时间 |
| 关卡进度 | 未开始、进行中、已完成；最近检查点、当前草稿、最后保存时间 |
| 知识学习证据 | 关联知识点、独立完成表现、提示情况、后续复习结果 |
| 成果与奖励 | 获得条件、领取事件、时间；作品与修改记录按功能阶段加入 |

历史中的客观题成绩由服务端核验，奖励也由服务端发放。历史保存内容版本和必要题目快照，后续修改题目不会改变此前记录的含义。

### 9.2 历史页面

时间线展示日期、关卡名称、完成状态和本次学习目标。允许按时间、年级学期、完成状态筛选；进入详情后查看作答、提示使用和解释。

家长汇总提供最近学习、独立完成情况、复习建议和代表作品。没有足够记录时显示“正在积累学习记录”，不输出虚构的掌握比例。

有效学习时长按页面前台与实际交互估算，暂停和切到后台的时间不累计；该数值标注为估算，不等于注意力或学习效果。

### 9.3 保存与同步规则

- 每次提交答案后保存作答；关卡切换、暂停和完成时更新检查点。
- 明确展示“保存中、已保存、待同步、保存失败”的状态和重试入口。
- 已确认同步到云端的进度，在其他设备登录后可继续。
- 临时断网时，本机暂存当前作答，恢复连接后重试；首发不承诺全部课程离线可用。
- 每条提交携带唯一编号，重复点击或网络重试不能生成重复作答、重复奖励。
- 作答历史采用追加记录，不能用另一个设备的旧状态覆盖已有记录。
- 同关卡在两个设备同时编辑时，对检查点执行版本校验；发生冲突保留草稿，提示选择继续位置。
- 聚合进度根据有效作答与完成事件计算。完成记录保留，重玩新增一次尝试。
- 退出登录时隔离或清理账号对应的本机缓存，避免共享设备显示上一账号的记录。

## 10. 内容数据与生产流程

现有仓库的小学语文数据包含 4,851 个知识点、2,889 条关系，可作为知识目录、来源追踪和关联线索。知识点记录不能直接替代题库或完整课程。

生产流程：导入 → 检查结构与来源 → 整理学习目标 → 核对年级教材 → 编写剧情和活动 → 校对答案与解释 → 试用 → 发布版本。

每个发布关卡至少具备：适用年级学期、学习目标、来源映射、材料、活动规则、答案或评价要点、提示、解释、资源和版本号。

内容建设要求：

- 核对新旧教材版本与章节，无法确认的条目不直接作为正式教学依据。
- 抽取置信度用于安排审核优先级，不能当作知识正确率。
- 同一概念的多条记录需整理；既有关系用于辅助，跨年级能力路线另行建立。
- 拼音、规范字形、笔顺和音频需要校对后的补充资源。
- 原创阅读材料和题目优先，引用材料记录来源与使用条件。
- AI 用于起草与提出变式，正式内容需要审核；首发使用预先发布的稳定内容包。
- 阅读和表达题明确可接受答案与评价依据，支持合理的多种表达。

仓库声明使用 PolyForm Noncommercial 1.0.0。原型按非商业用途规划，商业使用前需取得适当授权或更换数据来源。补充材料和媒体资源分别管理使用权限。

## 11. 系统实现规划

### 11.1 模块划分

响应式 Web 客户端 → 业务服务 → 数据库与媒体资源。

客户端负责场景、活动交互、阅读、草稿与保存状态；业务服务负责认证、内容访问、判题、进度、历史与奖励；数据库保存账号、学习档案、发布内容和学习记录。图片、音频等媒体独立存储并按需加载。

关卡采用结构化配置：故事段落、资源、活动类型、题目、反馈、奖励分别定义。新关卡优先配置内容，复用已有交互组件。

### 11.2 核心数据对象

| 数据对象 | 主要职责 |
|---|---|
| 用户账号、会话与验证记录 | 注册登录、恢复、账号状态 |
| 学习档案 | 昵称、年级学期、归属关系 |
| 教材、知识点与关系 | 来源、版本、章节和知识关联 |
| 地图、章节与关卡 | 故事结构、发布状态和学习目标 |
| 题目与内容版本 | 题型、材料、答案、解释和历史版本 |
| 学习尝试与作答 | 追加保存的活动和答案证据 |
| 关卡检查点与草稿 | 跨设备继续学习、冲突检测 |
| 学习证据与复习安排 | 可解释的状态与后续练习 |
| 奖励与收藏 | 去重发放、书屋和手册 |

首发即建设服务端身份验证、归属校验、判题和学习记录。仅使用浏览器本地存储的演示不能作为完成注册登录与跨设备历史功能的交付。

### 11.3 上线依赖与运行维护

正式运行需要网站域名与 HTTPS、业务服务、数据库、媒体存储、邮件投递服务及备份机制。开发、试用和正式环境分开，使用测试账号与测试邮件验证流程。记录接口错误、保存失败和投递失败，便于排查；日志避免记录密码、验证令牌与不必要的个人信息。

## 12. 开发阶段与交付边界

### 第一阶段：基础平台与六个年级样章

- 完成响应式页面和基础视觉体系。
- 一至六年级各制作 2 个真实可玩关卡，共 12 关。
- 完成账号注册、邮箱验证、登录、找回密码和退出。
- 完成一个学习档案、游客体验与记录导入。
- 完成地图、提示、过关、奖励、基础手册和简单书屋。
- 完成学习历史详情、家长汇总、检查点保存和跨设备继续。
- 使用真实后端保存数据；作品集、自动口语评分和自动作文评分不属于此阶段。

交付验收以实际完成“注册 → 登录 → 闯关 → 保存 → 查看历史 → 更换设备继续”全过程为准。

### 第二阶段：一至二年级完整内容

完成四个学期的内容核对、关卡、校对音频、书写活动和亲子提示。按初步规模对应 96 个主线关卡。分别开展目标年级试用。

### 第三阶段：三至四年级完整内容

完成四个学期的阅读、观察、复述与习作内容，增加作品草稿、修改清单和阶段成果。按初步规模对应 96 个主线关卡。

### 第四阶段：五至六年级完整内容

完成四个学期的多材料阅读、资料整理、综合表达和毕业作品，完善整本书交流与项目任务。按初步规模对应 96 个主线关卡。

后续根据实际使用需求加入多学习档案、内容管理后台、跨设备作品附件和可安装 Web 应用体验。内容制作与审核工作独立估算，不能仅按页面数量估算整体开发工作量。

## 13. 验收与试用标准

| 方面 | 验收重点 |
|---|---|
| 账号 | 注册、验证、重复注册提示、登录、错误密码、恢复与退出可完成；邮件状态真实 |
| 归属隔离 | 不同账号互相无法读取或修改学习记录，退出后共享设备不混入旧记录 |
| 学习闭环 | 任务、示范、独立尝试、提示、解释、迁移任务与结果可完整体验 |
| 记录准确性 | 首次与重试分别保留，内容版本可追溯，重复提交不重复计分或发奖 |
| 同步 | 刷新、重登、跨设备可恢复已保存进度；断网重试与双设备冲突有明确反馈 |
| 多终端 | 典型手机、平板、PC尺寸可用；旋转、软键盘、缩放、触控与键盘操作正常 |
| 内容质量 | 年级和教材映射有核对记录；答案、提示与解释经过校对；无效题可下架修订 |
| 趣味性 | 目标年级孩子理解任务，操作能推进故事，完成后有可见成果 |
| 学习证据 | 能从新材料任务和后续复习观察理解变化，不把点击、在线时长或奖励当成学习效果 |

样章阶段邀请覆盖低、中、高年级的孩子试用，分别记录卡住的位置、需要多少成人协助、解释是否有帮助、换题后能否完成，以及是否愿意再次进入。依据试用结果调整文字量、任务长度、操作方式和反馈。
